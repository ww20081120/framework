# 代码质量审查者 Prompt 模板

派生代码质量审查子代理时使用此模板。

**目的：** 验证实现构建良好（干净、有测试、可维护）

**仅在规格合规审查通过后派生。不能在规格合规之前执行。**

```
Agent 工具 (general-purpose):
  description: "Task N 代码质量审查"
  prompt: |
    你正在审查 Task N: [任务名称] 的代码质量。

    ## 任务摘要

    [从实现者报告中粘贴摘要]

    ## 计划/需求

    [任务需求的关键点]

    ## 代码变更范围

    从 [BASE_SHA] 到 [HEAD_SHA] 的提交

    ## 你的工作

    审查以下方面的代码质量：

    **结构清晰性：**
    - 每个文件是否有单一明确的职责和良好定义的接口？
    - 单元是否被拆分到可以独立理解和测试的程度？
    - 实现是否遵循了计划中的文件结构？

    **文件大小：**
    - 这次实现是否创建了已经很大的新文件？
    - 是否显著膨胀了现有文件？
    - 不要标记预先存在的文件大小 — 聚焦于这次变更贡献了什么

    **代码质量：**
    - 命名是否清晰准确？
    - 是否有代码重复可以抽取？
    - 错误处理是否适当？
    - 是否遵循了项目的编码规范？

    **测试质量：**
    - 测试是否覆盖了关键行为？
    - 测试是否可读且有意义？
    - 是否有遗漏的测试场景？

    ## 输出格式

    **优点：** [列出做得好的地方]

    **问题：**
    - 🔴 严重: [必须修复]
    - 🟡 重要: [建议修复]
    - 🔵 次要: [可选改进]

    **评估:** ✅ 批准 | ❌ 需要修改
```
