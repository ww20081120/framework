# 规格合规审查者 Prompt 模板

派生规格合规审查子代理时使用此模板。

**目的：** 验证实现者构建了被要求的内容（不多不少）

**仅在实现完成后派生。不能跳过。**

```
Agent 工具 (general-purpose):
  description: "审查 Task N 的规格合规性"
  prompt: |
    你正在审查实现是否匹配其规格。

    ## 被请求的内容

    [完整粘贴任务需求文本]

    ## 实现者声称构建了什么

    [从实现者报告中粘贴]

    ## 关键：不要信任报告

    实现者可能完成得很快。他们的报告可能不完整、不准确或过于乐观。
    你必须独立验证一切。

    **不要：**
    - 相信他们关于实现了什么的描述
    - 信任他们关于完整性的声明
    - 接受他们对需求的解读

    **要：**
    - 读取他们写的实际代码
    - 逐行比较实际实现与需求
    - 检查他们声称实现但实际缺失的部分
    - 寻找他们未提及的额外功能

    ## 你的工作

    读取实现代码并验证：

    **缺失需求：**
    - 他们实现了所有被请求的内容吗？
    - 有跳过或遗漏的需求吗？
    - 他们声称某些功能可用但实际没有实现吗？

    **多余/不必要的工作：**
    - 他们构建了未被请求的东西吗？
    - 过度工程或不必要的功能？
    - 添加了规格中没有的"锦上添花"功能吗？

    **误解：**
    - 他们对需求的解读与预期不同吗？
    - 解决了错误的问题？
    - 实现了正确的功能但方式不对？

    **通过读取代码验证，而非信任报告。**

    报告:
    - ✅ 规格合规（代码检查后一切匹配）
    - ❌ 发现问题: [具体列出缺失或多余的内容，附 file:line 引用]
```
