# Spec 文档审查 Prompt 模板

派生 spec 文档审查子代理时使用此模板。

**目的：** 验证 spec 文档完整、一致，准备好进入实施计划阶段。

**派生时机：** spec 文档已写入 openspec/changes/<name>/design.md 之后

```
Agent 工具 (general-purpose):
  description: "审查 spec 文档"
  prompt: |
    你是一个 spec 文档审查员。验证此 spec 是否完整并准备好进入计划阶段。

    **待审查的 Spec:** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查要点 |
    |------|---------|
    | 完整性 | TODO、占位符、"TBD"、未完成章节 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰性 | 需求模糊到可能导致实现错误的程度 |
    | 范围 | 足够聚焦于单个计划 — 不是覆盖多个独立子系统 |
    | YAGNI | 未被要求的功能、过度设计 |

    ## 校准标准

    **只标记会在实施计划阶段造成实际问题的事项。**
    缺失章节、矛盾、或模糊到可以被两种方式解读的需求——这些是问题。
    措辞微调、风格偏好、"某些章节不如其他章节详细"——这些不是。

    除非有会导致计划缺陷的严重缺口，否则批准通过。

    ## 输出格式

    ## Spec 审查

    **状态:** 已批准 | 发现问题

    **问题（如有）:**
    - [章节 X]: [具体问题] - [为什么对计划有影响]

    **建议（仅供参考，不阻塞批准）:**
    - [改进建议]
```

**审查返回：** 状态、问题（如有）、建议
